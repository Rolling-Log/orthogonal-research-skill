# orthogonal-research-skill

目标是让读者能解释对象如何运作、差异为何形成、自己的工作需要比较什么，以及哪些重要判断仍不确定。保留纵向演变、横向差异和两轴交汇的主干；篇幅、来源数和图数只服务这些理解结果。

## 按需读取

- 开始研究时读 [research-protocol.md](references/research-protocol.md)：输入、证据合同、检索与停止条件。
- 定问题时及交付前读 [adversarial-review.md](references/adversarial-review.md)：目标机制、强反方、区分证据与修订。
- 写作和构建时读 [report-spec.md](references/report-spec.md)：主结构、阅读路径、引用和排版。
- 准备交付时读 [reusable-delivery.md](references/reusable-delivery.md)：同一研究生成 PDF、HTML 和可编辑资料；按需查询组件协议，不加载或重写整套前端。
- 使用图片、数据图或图谱时读 [visual-system.md](references/visual-system.md)。
- 需要行为或格式范例时读 [examples.md](references/examples.md)。升级审查需要能力迁移依据时读 [v1-regression-matrix.md](references/v1-regression-matrix.md)。

这些资源已经集成，不要求安装其他 skill。

## 1. 识别用途并建立研究包

先从用户请求提取对象、工作或探索目的、特别关注点、地域、已知知识、阅读预算与研究截面。区分用户明说、合理推定和暂缺信息；不编造职业能力或时间限制。

用途明确就直接继续。只有对象或用途的不同解释会实质改变研究边界时，才问 1–2 个简短问题；不重复问已给出的信息，不默认进入 grill me。只缺知识水平或阅读预算时，按入门读者组织、提供核心与深入阅读路径。用户自己也不知道或只想探索时，从“是什么—如何运作—怎样演变—今天有哪些路线—重要争议与未知”开始，不把探索暗改成采购或立项。

在用户项目内建立研究包；用户未指定输出位置时运行（默认当前工作目录，目录冲突自动另建）：

```text
python <skill-dir>/scripts/init_workspace.py --subject "对象"
```

以返回 JSON 的 `workspace` 绝对路径为后续工作目录。指定目录则传 `--destination "用户目录"`；明确指定单文件或平铺交付时遵从用户。不得覆盖已有目录。默认包：

```text
<对象>_横纵分析报告_<日期时间>/
├── report.md
├── study.json
├── delivery/                 正式 PDF、HTML、Markdown 与数据；构建后生成
├── sources/
│   ├── sources.json
│   └── research-log.json
├── data/
│   └── components.json       按需选用的交互与静态说明，允许空列表
├── visuals/
├── images/
└── build/
    ├── report.html
    ├── report.build.json
    ├── research-check.json
    └── qa/
```

`sources.json` 保存来源、主张与证据；`research-log.json` 复用来保存简报、问题优先级、重要未知、检索和停止理由，不再建第二套台账。来源 ID 稳定为 `S001`……，重跑复用。新研究标 `method_version: "3"`、`coverage.balance_policy: "diagnostic"`；旧报告缺政策时仍按旧 strict 规则重建，不能静默迁移。

## 2. 先扫领域，再按问题研究

先扫描对象定义及易混淆概念、必要机制、主要参与者与路线、直接和间接替代、关键历史转折、争议与可能遗漏。用户当前关注点不能提前排除会改变理解的重要未知。扫描后校正必答问题及优先级，说明不展开内容的理由。

把第一性原理落实为：要解释或实现什么目标，哪些机制和约束不可跳过，有哪些可行路线，什么观察能比较它们。不要用自评分或篇幅代替这四件事。

必须使用环境实际可用的联网能力打开原始页面或文档；搜索摘要只提供线索。对全球性对象跨中文、英文及必要的当地语境寻找遗漏，关键词按定义、起源、转折、替代、效果、风险和反证选择，不为完成固定轮次重复同义词。学术或技术范式定位原论文、正式版本和相关复现，说明预印本状态。

优先寻找原始文件、数据、观察和测量，按主张选择证据角色：公告能核验“公布了什么”，原创测量可能更适合“实际得到什么”。转载、翻译、镜像共用证据根；域名数量不等于独立证据。社区口碑只在体验、故障或采用问题相关时使用，并披露样本窗口及偏差。

来源语言、地区、组别、数量和层级保留为覆盖诊断。V3 不用 20%–80% 比例或固定来源数阻断；也不因比例合格认定覆盖充分。真实缺口在 `limitations` 说明缺什么、偏向什么、影响哪些判断；只调整受影响判断，不按语言比例统一降级。坏引用、同源语境冲突和无有效证据仍必须修复。

对象复杂且环境允许时并行分工纵向、横向和补充材料；简单对象不用强凑三组。各组返回原始 URL、时间口径、支持范围、冲突与未知，合并时检查循环印证。

### 获取失败

若关键问题需要平台内搜索、视频字幕、独立使用记录，或现有检索遗漏了重要的最新进展，按需读 [retrieval-tools.md](references/retrieval-tools.md)。其中的 Agent-Reach 是可选的安装与诊断工具；采集由实际可用的上游工具完成。先检查能力，再针对缺口调用；不为每份报告安装工具或遍历所有平台。

优先使用现有搜索、浏览或获取工具。确需文本而工具失败时，可调用有界回退：

```text
python <skill-dir>/scripts/proxy_fetch.py "https://..." --json -o <workspace>/build/fetched_page.txt
```

检查状态、HTTP 状态、最终地址、内容类型、字节和完整性；200 不等于有效研究正文。脚本保留 TLS 验证、读取已有 HTTP 代理配置、不改用户设置；默认正文上限 2 MB，压缩和非文本响应明确拒绝。`--timeout` 限制网络等待与正文期限，系统 DNS 不承诺精确按该秒数结束。其他代理类型使用环境工具。

仍失败则记录真实错误与替代尝试，寻找合法一手替代；不推定失败原因，不绕过访问控制，不做无关站点检查。受阻影响核心判断时在摘要和“研究范围与限制”披露并限缩，无法核验的信息写“公开信息暂缺”。

## 3. 双轴分析与交汇

**纵向**用“背景约束 → 选择及备选 → 结果 → 新约束”还原从起源到截面的演变。解释最初形态与今天的差异、推动者、真正改变方向的转折、路径依赖和危机；按实际机制划阶段，不按年份或固定阶段数填槽。团队、融资、版本等只在适合对象且影响机制时展开。

**横向**先建候选池，按需求重叠、资源竞争或路线参照选择比较对象，说明纳入与排除理由。无直接竞品时比较间接替代、上一代或潜在路线；对象少就深挖，多就选能解释主要差异的代表，不固定 3–5 家。统一版本、时间、地域、定义和测量条件；无法统一就做条件比较。参数表之后解释差异如何形成、谁会选择、代价是什么。人物和概念不能硬套价格、商业份额和用户投诉模板。

**交汇**解释历史选择怎样影响今天的优势、包袱或路线差异，比较对象自身的演变路径，写明持续条件及替代解释。形成真正依赖两轴的判断，不强凑三条洞察或三个未来剧本。涉及未来工作判断时才展开有机制、时间、触发、反证和可观测指标的情景；无依据不填概率。

每个关键事实映射到现有 claim。错误会改变核心机制、路线比较、风险或行动的高影响主张，再补 `impact_reason`、`kind` 和 `evidence` 中可复找的定位、实际支持、支持边界、时间口径；高影响混合根补 `root_keys`。细则见研究协议，不给每句背景灌字段。

关键推断、争议与假设在 claim 的 `review` 记录最强合理替代、区分证据、撤销或收窄条件及真实修订。把反方前移到选题与检索；“也有风险”不算反方，找不到反证不等于排除。纯公告日期按原来源核验，无需硬造另一套因果解释。缺证可诚实悬置，不能写 verified/high。

### 何时进入写作

能解释必要机制和关键转折，比较对象及口径可辩护，承重证据与强反方已处理，剩余未知已明确其影响，才进入正文。停止依据是关键问题得到支持、限缩或悬置且继续研究不太可能改变它们；来源数、连续空轮次仅作线索。核心未决先补最可能改变结论的证据；客观不可得就交付范围清楚的有限研究，不能声称该机制已证实。

## 4. 写成读者能用的报告

在“一句话定义”（含对应来源说明）之后、执行摘要之前，插入能帮助读者辨认研究对象的代表图片。优先一张；确需展示不同形态时用 2–4 张单行横排，每张辅助文字不超过 10 个字符。给图片正常展示空间，让后文自然下移，不压缩正文来挤进原有空隙。选图、来源与构建语法见 [visual-system.md](references/visual-system.md)。

主干顺序保留：一句话定义 → 纵向分析 → 横向分析 → 横纵交汇 → 信息来源与方法说明，不生成目录页。摘要中融入用途、必要机制、主要问题和重要未知；阅读路径使用实际章节标题，不编页码或承诺不存在的 PDF 内链。

未熟悉领域的读者需要的术语在首次使用时解释。证据稿先锁定事实、判断、反证和引用，阅读稿再改善叙事、段落和转场；实质发现需回到证据稿同步修订。正文中能看见目标与约束、主要判断的证据和强替代、适用条件与会使判断改变的观察，不另加两章方法口号。

篇幅按问题、证据和读者预算分配；明确要完整深度报告时保留足够纵横展开。核心/深入阅读路径让读者选读，不能为了短而删必要机制，也不能靠同义反复达到旧 1–3 万字。风格和排版细则见报告规范。

引用语法：

```markdown
该选择帮助技术复用，但尚不能推定利润率上升。{{@S014,@S019 | 两份资料的测试条件不同，只比较机制。}}
```

构建器按首次出现顺序显示紧凑深蓝上标 `[1][2]`，必要说明放对应段落、列表、表格单元格或图来源之后，最终隐藏内部 ID。标题、代码、图片替代文本不支持引用标记。文末按首次顺序列全来源简称、发布者、标题、完整 URL、发布日期与访问日；无发布日期写“unknown”，在来源 notes 说明，不能造日期。引用与文献必须双向一一对应。

## 5. 按解释作用选图

数据写入 `data/visuals.json` 后运行：

```text
python <skill-dir>/scripts/render_visuals.py data/visuals.json --output-dir visuals
```

支持 timeline、bar、line、donut、matrix、knowledge_graph。图必须有时间、单位、口径、来源与正文解释；无可比数据用定性表，不造数。图谱逐边标出处，事实与假设区分；太密就拆图，不能缩成不可读。图数、节点推荐数和连续纯文字页数只用于发现阅读问题，不为了凑数插图。

产品报告必须用可取得且权属清楚的真实产品图、界面或演示截图解释必要形态或用法；数量按作用选择，单张够用无需再填一张。确实无法取得时披露素材缺口及影响，不能以 AI 图冒充实物或证据。记录来源、作者/机构、许可与访问/截图日。位图插图约 78% 正文宽，数据图和图谱全宽。

受支持原图直接使用。需要转换时先确认当前环境提供兼容的 Pillow 或其他图像工具；公开包不携带平台专用的图片转换二进制。图片边界见视觉规范和报告规范。

## 6. 结构检查、构建与独立验收

先运行：

```text
python <skill-dir>/scripts/check_research.py sources/sources.json --output build/research-check.json
```

这只检查 ID 关系、日期和高影响记录的可审查性，不能证明原文支持、因果程度、检索充分或读者理解。由独立审查者识别全部承重判断后核对原文；不能只审作者自标高影响的条目。按对抗审查处理重大遗漏、口径、因果和读者流，反证后同步摘要、正文、表图与台账。

完整研究默认同时交付 PDF 和 HTML，不先让用户二选一；明确只要一种则遵从。两种形式共用完整正文、数据、来源与研究截面，不改变本节以前的写作要求，不把 HTML 浓缩成少量展示卡片。网页新增的关键材料与条件必须有 PDF 静态对应。

按理解任务选择已有组件，填研究内容和证据，不照搬上一个对象的规则。先运行 `python <skill-dir>/scripts/report_components.py --list`，再用 `--describe <kind>` 只读选中的协议。只有真实缺口才扩展一个独立组件并验证；不因为换题而重写页面、引用、图表、导出或笔记功能。详细规则见 [reusable-delivery.md](references/reusable-delivery.md)。

确认 `study.json` 中对象类型、标题、研究截面和文件路径后构建：

```text
python <skill-dir>/scripts/build_delivery.py <workspace>/study.json
```

有旧六类 SVG 图时在 `study.json` 设置 `visual_spec: "data/visuals.json"`；没有则省略，不创建空图文件凑交付。旧 `build_report.py` 保留，继续用于独立 PDF 或历史报告重建；它生成的 HTML 调试稿不等同于新的交互交付。

Python 3.9+；内置 PDF 依赖与中日韩字体，无需系统字体或浏览器。JPEG、非交错 8-bit PNG 和规范 SVG 使用报告相对路径；不支持格式按提示修复。PDF 封面与 HTML 自动显示全文字数和粗估阅读时间，改内容后重建；完整口径与 `reading_metrics` 见报告规范。封面无作者，`--author` 仅元数据。

修改脚本或核验环境时运行自检：

```text
python <skill-dir>/scripts/init_workspace.py --self-test
python <skill-dir>/scripts/build_report.py --self-test
```

将真实 PDF 每页渲染为图片逐页检查：字体、全宽正文、原有标题配色和竖条、引用说明、表格、图片、图谱、页眉页脚与分页。抽取文字不能代替视觉检查。构建日志的 render_status 只说明渲染，research_review_status 不被构建成功升级为研究通过。

承重错误或渲染失败先修复；无法解决时保留材料并说明尚未完成或限定产物。交付实际 PDF、HTML 和研究包绝对路径，说明影响结论的限制。只有实际运行的平台才能称实机通过；其他平台写“静态兼容，未实机验证”。方法版的效果也只能按真实比较结果陈述，不能因字段齐全宣称普遍提升。
