# 使用与修订示例

这些行为例说明如何使用方法，不能把示例公司、日期、数值或 example.com 当真实材料。可运行的渲染样例见 sample_report.md、sample_sources.json 和 sample_visuals.json；它只验证结构与排版。

## 输入怎样改变行为

| 用户请求 | 行为 |
|---|---|
| “我刚加入一家机器人公司的产品团队，下周讨论技术路线；了解过去五年和全球替代，我有 40 分钟，做 PDF。” | 已给工作、范围与预算，直接执行；先扫描必要机制，再重点解释路线和权衡。阅读路径分核心与深入，不再问职业与时间。 |
| “帮我深入研究一下机器人。” | 名称可能指产业、某类产品或技术；若会改变边界，问一个简短对象/用途问题。不能无条件推成采购。 |
| “我也不知道自己要关注什么，先帮我建立整体认识。” | 使用入门探索路径，讲定义、机制、演变、现状路线与未知。初扫发现重要问题后校正重点，不把新人不懂当作不能开始。 |
| “同一个机器人领域，我做销售，需要讲明差异与适用场景。” | 保留相同必要机制和历史转折，改变比较优先级与解释语言；参数上限不能写成客户一定得到的效果。 |
| “完整深入研究这个概念的提出、演变、争论和替代，不需要压缩。” | 给充分的纵横展开，不套商业竞品表，也不自动变成摘要；篇幅由证据与解释需要决定。 |
| “先 grill me，帮我把研究目标问清楚。” | 按明确请求做详细访谈，但不要求用户提前给出陌生领域答案。 |
| “什么是激光雷达？两句话回答。” | 直接简答，不启动完整报告、制图或 PDF。 |

未指定位置时使用初始化返回的桌面研究包；指定位置则尊重用户。均以真实研究截面、来源与重要限制交付，不能从范例抄研究结论。

## 第一性原理怎样进入正文

例如要研究“模块化是否帮助扩展产品线”，先明确目标是减少重复工程，约束包括接口兼容和协调成本，再比较复用、重新设计与部分复用等路线。历史只显示共用组件，不能直接推出净成本或利润优势。横向可检验同条件项目的工程量与协调成本，交汇解释早期接口选择如何限制后来路线。

这不是新加“第一性原理”口号章。目标、约束、选择、实际结果及尚未验证的部分放在对应历史、比较和交汇段。

## 二遍改写保留边界

以下日期与来源均为**虚构写作示意**。证据稿：

```markdown
模板记录显示，2019 年开发的核心组件用于 2021 年和 2023 年两条产品线。资料没有同条件开发成本。我的判断是，这能证明技术复用，可能减少重复工程；净成本和利润影响仍不能裁决。{{@S012,@S027 | 两个系列的工程与协调成本没有同口径对照。}}
```

阅读稿：

```markdown
2019 年的核心组件后来进入两条产品线，分别出现在 2021 年和 2023 年。早期工程边界为复用留下了条件。

**技术复用是可核对的，经济净收益仍未定。**我的判断是，它可能减少重复工程；但渠道需求也可能同时推动复用与扩张，协调成本可能抵消节省。要区分这些解释，需要同条件项目成本，现有资料没有。{{@S012,@S027 | 两个系列的工程与协调成本没有同口径对照。}}
```

核对事实、支持边界和引用相同；不能润色成“当时未带来销量”“必然降低利润成本”等无来源句。新反证若改变判断，返回证据稿同步台账、摘要和表图。

## 反方与缺证怎样修订

原判断“复用必然降低成本”的承重假设是节省大于接口/协作开销。强反方是渠道扩张同时推动复用且增加协调成本。区分证据应测同条件净工程成本，只有复用时间线不能裁决。

真实找到相反净成本后，只撤回成本优势，保留已核验的复用事实。若未取得区分数据，就收窄为“存在技术复用，经济净收益未知”。review.revision 写这项真实收窄，不能只填“已完成反方审查”。

如果某项关键假设没有可用原文，可用下面的**结构片段**。合入完整台账时同步其他 ID 关系；空证据不能支持该假设：

```json
{
  "id": "C030",
  "claim": "扩大接口复用可能减少总项目成本，暂无法判断。",
  "source_ids": [],
  "status": "unresolved",
  "confidence": "low",
  "kind": "hypothesis",
  "impact_reason": "会改变是否扩大投入。",
  "evidence": [],
  "support_gap": "未取得同条件净成本观测；不可由复用公告推出。",
  "review": {
    "alternative": "接口兼容和协调开销抵消重复工程节省。",
    "discriminating_evidence": "同条件项目总成本对照，目前没有。",
    "change_condition": "净成本无优势则撤回成本优势；有优势再限于测试条件。",
    "revision": "撤去扩大投入结论，保留待验证假设。"
  },
  "counterevidence": []
}
```

若一篇原创测试文章也引用厂商公告，对该主张的 evidence 标 `mixed_source: true`，root_keys 只列实际用到的“原公告根”和“原创测试根”；不要把整个域名当一个根或全部当独立测量。单根直接继承 source.independence_key。完整 evidence 合同见 [research-protocol.md](research-protocol.md)。

## 常见失败

- 同图混用注册、月活和付费用户：拆图或取得同口径，不能强排名。
- 仅公告规格却声称实际效果、仅时间相邻却声称因果：找适合证据，否则限缩。
- 明确工作信息仍先发长问卷，或探索请求被改成采购：纠正输入提取与范围。
- 来源语言比例满足却漏关键路线，或偏斜就给全部结论降级：检查具体遗漏及受影响主张。
- 为来源、剧本、字数、图片数量填槽：删冗余，补真正必要机制与证据。
- 编号不存在、文献顺序错误、数据文件不存在：修复结构，不能跳过检查。
- 结构检查/构建成功就宣布研究真实：独立核对承重原文与限制，逐页核验 PDF。
