# 可视化、知识图谱与图片规范

## 共同原则

- 最终产物是 SVG/PNG/JPEG，不是 Mermaid、DOT、Vega、XML 或代码块；
- 每张图只回答一个主要问题，标题优先写结论；
- 使用 v1 配色：深蓝 `#1A5276`、绿 `#1E8449`、浅蓝 `#2E86C1`、紫 `#5B2C6F`；红色只表示风险或假设；
- 不使用 3D、双 Y 轴、装饰性雷达图、彩虹色板、无意义阴影或截断轴夸大差异；
- 图表和图谱由同一纯 Python 场景模型生成 SVG，并由 PDF 构建器直接绘制；不需要浏览器、外部图布局程序或 SVG 栅格化；
- 每张图包含来源 ID、统计时间、单位和必要口径；正文紧接一句“这张图证明什么、不能证明什么”。

## 顶层 JSON

```json
{
  "visuals": [
    {
      "type": "bar",
      "output": "chart_market_share.svg",
      "title": "A 在核心市场保持领先",
      "subtitle": "2025 年出货量份额",
      "source": "S021；截至 2025-12-31",
      "unit": "%",
      "labels": ["A", "B", "C"],
      "values": [42, 31, 18]
    }
  ]
}
```

`output` 必须是安全相对路径并以 `.svg` 结尾。所有文字都会转义；不得放 HTML。先运行：

```text
python scripts/render_visuals.py data/visuals.json --output-dir visuals
```

## 时间线 `timeline`

用于离散转折，不用于连续指标。保留 2–10 个改变方向的节点；更多时按阶段拆图。

```json
{
  "type": "timeline",
  "output": "timeline.svg",
  "title": "五次转折定义了当前路径",
  "source": "S001、S005、S011",
  "events": [
    {"date": "2019", "label": "项目启动"},
    {"date": "2022-03", "label": "首次公开发布"}
  ]
}
```

## 条形图 `bar`

字段：`labels`、`values`、可选 `unit`。最多 15 类，数值非负。按值排序；从零开始；直接标数值。类别标签较长时优先横向条形图。

## 折线图 `line`

字段：`labels`、`series`；`series` 形如 `[{'name':'对象','values':[1,2]}]`。2–24 个点、最多 4 条线。时间间隔不等时在字幕披露，不得伪装成等间隔。跨币种、口径或样本变化时分图或标准化并说明。

## 环形图 `donut`

字段：`labels`、`values`；只用于 2–6 个互斥类别且总量有明确含义的构成。超过 6 类改用条形图。不要用环形面积暗示不准确的绝对差距。

## 定位矩阵 `matrix`

字段：`x_label`、`y_label`、`points`。点格式：`{"label":"A","x":0.8,"y":0.6,"group":"target"}`，x/y 为 0–1。两轴必须能解释方向；主观综合评分必须说明评分规则和作者判断属性。

## 知识图谱 `knowledge_graph`

先从来源提取“实体—关系—实体”三元组：

```json
{
  "type": "knowledge_graph",
  "output": "ecosystem.svg",
  "title": "生态由产品、渠道与资本三层构成",
  "source": "S003、S017、S024",
  "nodes": [
    {"id":"core","label":"研究对象","group":"core","level":0},
    {"id":"p1","label":"核心产品","group":"product","level":1},
    {"id":"c1","label":"渠道伙伴","group":"organization","level":2}
  ],
  "edges": [
    {"from":"core","to":"p1","label":"推出","source":"S003","kind":"fact"},
    {"from":"p1","to":"c1","label":"触达","source":"S017","kind":"hypothesis"}
  ]
}
```

约束：

- 恰好一个 level 0 中心；3–18 个节点，推荐 8–18 个；层级 0–4；
- 节点短标签不超过 14 个汉字；复杂解释放正文；
- 人物、组织、产品、技术、市场按 `group` 区分；
- 边标签用 1–6 个汉字的动词，不用“相关”“联系”；
- `fact` 为实线，`hypothesis` 为红色虚线；每条边必须带 `source`；
- 多对多关系过密时拆为“人物与资本”“产品与技术”“商业生态”等图，不缩小到不可读；
- 不展示无法验证的私人关系或敏感个人信息。

每张图谱后写“读图”：三个关键节点、两条关键关系、能说明什么、不能说明什么。静态核心图必须 30 秒可读；可选交互稿不能替代 PDF 静态图。

## 图片与版权

优先顺序：官方截图和媒体资产、财报原图、论文图、许可明确的 Wikimedia Commons。记录文件名、标题、作者/机构、原始 URL、许可、访问或截图日期。不得下载来源不明、低清水印或权属不明图片。

产品报告至少选择 2 张能解释产品形态、核心界面或典型使用方式的真实产品图、官方截图或公开演示截图，并嵌入最相关的正文位置。若权属、清晰度或访问条件导致无法取得，必须在“研究范围与限制”说明，不能用纯文字或数据图静默替代。

JPEG/PNG 位图插图和产品截图以约 78% 正文宽度居中，避免连续大图打断叙事；由 `visuals.json` 生成的 SVG 数据图、时间线、矩阵和知识图谱保持全宽及原有字号，不应用位图缩放规则。

截图只用于记录公开界面或网页状态，标注日期；不把截图当统计数据原始来源。生成式图片只能做明确标注的概念示意，不得模拟历史现场、产品实拍、人物照片或证据材料。

## PDF 验收

- SVG 必须显示为图而不是源码；
- 中文无豆腐块、乱码和截断；
- 线条、图例、节点和边标签在 100% 缩放下可读；
- 图表标题、来源、单位与正文一致；
- 图谱无节点重叠、边穿文字或越界；
- 不出现连续三页纯文字，也不出现连续两页只有图没有解释；
- 图片不失真，图注与图片不跨页分离；
- 产品报告包含真实产品图或界面截图；位图插图宽度适中，数据图和图谱没有被连带缩小；
- “图 N｜结论型标题”为 8.5pt 深蓝粗体，来源说明为 7.2pt 灰字，均与 10.5pt 正文明显区分；
- 句末紧凑编号角标和段后说明不压图、正文或页码。

## 集成来源说明

本规范吸收成熟开源可视化 Skill 的通用做法：按问题选图型、先做输入校验、输出 SVG 成品、渲染后人工复核、图谱限制节点/边密度、区分事实与假设。实现已重写并完整放在本 Skill 的 `scripts/` 内；运行时不下载、不安装、不调用外部 Skill。
